# 实验与仿真记录

## 📖 说明

核心要求来自一条铁律：

> 仿真假设不能伪装成真实器件指标。

任何数字都必须能回答「它从哪来」，并且严格区分三类来源。

## 一、三级来源标注（强制）

| 级别 | 含义 | 记录要求 |
|---|---|---|
| **A｜实测 / 厂商标称** | 真买了的器件，数据手册或实验测出 | 型号 + 手册页码/版本 + 实测日期 |
| **B｜论文值** | 从文献引用 | 作者 + 期刊 + 年 + 卷页 + DOI |
| **C｜理论假设** | 缺失参数的合理默认值 | **显式标注为假设** + 取值理由 + 敏感度说明 |

**规则：**

1. **每个参数必须带级别标签**，没有例外。
2. **C 级参数必须集中列一张表**，单独可见——不能埋在正文里。
3. **选型表里没有的参数，就是没有。** 不许补一个数还装作它有出处。
4. 参数一旦从 C 级升到 A/B 级（拿到了实测或文献），**保留变更记录**。

## 二、记录模板

```markdown
# 实验记录 <编号> — <标题>
- **日期**：
- **执行人**：
- **目的**：
- **关联**：<论文 / 上一版记录 / issue>

## 1. 配置
| 项 | 值 | 来源级别 | 出处 |
|---|---|---|---|
| 工作温度 | 25 °C | A | 数据手册 p.12 |
| 关键增益系数 | — | **未定义** | 手册未给出 |
| 环境修正因子 | 0.95 | C | 假设，敏感度待测 |
| 材料参数 | 见附表 | C | 文献典型值，待实测 |

## 2. 参数缺口（必须单列）
- 关键增益系数：手册未定义 → 当前仿真无法给出唯一结果
- 实际转换效率：未定义
- 环境修正因子的取值依据：未定义

## 3. 过程
（步骤、脚本版本、随机种子）

## 4. 结果
| 指标 | 值 | 不确定度 | 备注 |

## 5. 失败与异常
（失败的尝试也要记，写明失败模式）

## 6. 结论与下一步
```

## 三、可复现四要素

任何一条结果记录，缺一不可：

1. **代码/脚本版本**（git commit hash 或文件哈希）
2. **随机种子**（仿真必记）
3. **完整参数表**（带来源级别）
4. **环境**（依赖版本、OS）

**缺任何一项，这条结果就是不可复现的**——如实标注，不要含糊。

## 四、参数缺口台账

维护一份**跨实验的缺口清单**，持续更新：

| 缺口参数 | 影响的结论 | 补法 | 状态 |
|---|---|---|---|
| 关键增益系数 | 直接决定输出量级 | 查手册 / 实测 | 未解决 |
| 环境修正因子 | 影响长期漂移估算 | 查手册 / 实验标定 | 未解决 |

**缺口未补齐时，任何依赖它的结论都要标「暂定」。**

## 五、诚实性要求

- **不许把假设写成指标**。仿真里的「探测效率 80%」如果来自假设，
  就不能在汇报里写成「本系统探测效率 80%」。
- **不许事后修改记录**。要改就**追加一条修订记录**，
  写明改了什么、为什么改。日志是 append-only。
- **失败必须记**。只记成功的日志没有复现价值。
- 不确定的数值，**宁可写区间 + 说明，也不要给一个假精确的数**。
- 如果某个结论在当前参数缺失下**无法给出唯一值**，就直说。

## 六、输出

- 默认：Markdown 记录文件（append-only）
- 参数表可同步导出为 xlsx，供仿真工作台读取
- 缺口台账单独维护一份，随时可查
